Gemma 3n: properties, capabilities, and the path of one token

You already know how to load a model. This lesson connects the settings you change in Dart to the work performed by the model and native runtime.

Scope note: ranges below are practical starting points, not promises. The exact model artifact, quantization, engine, and device determine the result. See the source list for the package and official references.

1. The big picture

Gemma does not produce a whole answer in one step. It repeatedly chooses the next token. The application supplies context and controls; the trained model supplies scores; the native runtime performs the high-volume numerical work. See the tokenizer reference for the text-to-token boundary and the Gemma 3n model card for artifact-specific capabilities.

2. How Flutter and Dart communicate with the model

  1. Create a message. The app creates Message.text from the user's input.
  2. Format the conversation. transformToChatPrompt applies formatting based on model and fileType.
  3. Stage the query. InferenceChat.addQuery calls the native session's addQueryChunk.
  4. Start prediction. generateChatResponseAsync asks the session for a response stream.
  5. Cross the bridge. MediaPipe commonly uses an EventChannel; LiteRT-LM uses its FFI/native stream path.
  6. Wrap the chunk. The package turns a returned string chunk into TextResponse(chunk).
  7. Render it. The app writes response.token into a buffer and rebuilds the response bubble.
Subtle but useful: “token” in the Dart API often means a decoded text chunk. It may represent part of a word, one tokenizer token, or several tokenizer tokens. The native tokenizer and detokenizer usually own the integer-ID conversion.

This is also where yesterday's bug lived: the Dart stream could look finished while native prediction was still unwinding. The stream is an observation channel; native session state decides when the next query is safe. Review Lesson 0001 for that lifecycle boundary, and compare the package's streaming API with the official Google AI Edge LLM Inference concepts.

4. Gemma 3n capabilities to explore

Gemma 3n is an on-device model family with modality and runtime support that varies by artifact. Treat each row as an experiment proposal, not an automatic guarantee for your E2B file.

baseline

Text chat

Ask the same question at 0.2, 0.7, and a higher temperature. Observe consistency, creativity, repetition, and useful detail.

context

Conversation history

Ask the model to remember a detail across turns. Increase history gradually and observe latency, truncation, and context limits.

vision*

Image understanding

Send an image with a specific question. Compare broad descriptions with questions about small details. Confirm supportImage and artifact support first.

audio*

Audio understanding

Try a short supported audio input and compare clear speech with background noise. Confirm exact variant and engine support first.

runtime

Streaming and cancellation

Measure time-to-first-chunk, total response time, and safe cancellation. Send a second prompt only after native completion.

model

Quantization trade-offs

Compare available model sizes or quantizations. Record memory, speed, answer quality, and modality support.

hardware

Backend comparison

Compare CPU with an available accelerator using the same prompt and seed. Measure speed and battery/thermal behavior.

application

Structured output

Ask for JSON, parse it in Dart, and display validation errors. This tests application reliability rather than adding a new model capability.

privacy

Offline operation

Install first, disable network, and test text inference. Separate model execution from downloads, telemetry, and app-level services.

* Vision/audio support must be checked against the exact model card and Flutter engine. A model family having a capability does not mean every converted artifact exposes it through every backend.

5. A controlled experiment

Keep constant

  • same model artifact and file type;
  • same prompt and conversation history;
  • same backend and random seed;
  • same device state where possible.

Record

  • time to first chunk;
  • total response time;
  • output token count/length;
  • repetition, truncation, and usefulness;
  • memory or thermal symptoms.

Run one baseline, change one setting, and repeat. Your result is evidence about that model/runtime/device combination—not a universal rule.

6. Check your understanding

1. Where are text characters converted into integer token IDs?

Usually inside the native runtime's tokenizer, after Dart has formatted and staged the prompt.

2. Does response.token always mean exactly one model token?

No. In this Dart API it is commonly decoded text returned as a chunk; a chunk can contain part of a word or multiple tokenizer tokens.

3. Which settings change the choice among next-token candidates?

temperature, topK, topP, and the random seed influence sampling. They do not enlarge the context window.

4. What is the difference between maxTokens and maxOutputTokens?

maxTokens is the whole context budget; maxOutputTokens caps the new response.

5. Why can a Dart stream look finished while native inference is not?

The Dart stream is an observation/communication channel. Native prediction has its own completion state; cancellation or stream detachment may happen before native PredictDone.

6. What must happen before prompt two is staged?

The first native generation must complete or be cancelled and fully unwind. Then—and only then—call addQueryChunk for prompt two.
