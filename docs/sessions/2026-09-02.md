# 2026-09-02

## Objective

Fix the native `PredictDone`/`AddQueryChunk` failure on the second prompt after
the D1 stop-token and generation-cancellation changes.

## Work Log

- Verified current HEAD (`4100bd3`) and baseline `flutter test`; the host test
  suite passes. The working tree contains pre-existing D1/platform changes.
- Looked up `GemmaService.sendMessageStream`, `_ChatScreenState._stopGeneration`,
  and the `flutter_gemma`/MediaPipe session lifecycle. The app currently exits
  its outer stream on a stop token without stopping and draining native
  generation; the UI also closes its local stream before native completion.
- Looked up `InferenceChat.generateChatResponseAsync`, MediaPipe
  `getResponseAsync`, and native `cancelGenerateResponseAsync`; the native
  session requires `PredictDone` before the next `addQueryChunk`.
- Looked up the D1 diff: the app downloads a `.litertlm` model while registering
  it as `ModelFileType.task`, matching the reported `fileType=task` log and
  routing the model to MediaPipe.
- Added a lifecycle-enforcing fake session and regression test; the test models
  the native error and verifies the second prompt succeeds only after the
  first stop-token turn has fully unwound.
- Modified `GemmaService.sendMessageStream`, `stopGeneration`, and model
  installation/recognition using the lookups above. Modified
  `_ChatScreenState._stopGeneration` so native completion precedes subscription
  cancellation.
- Verification: targeted service/widget tests, full `flutter test`,
  `flutter analyze`, and `git diff --check` all pass.
- Committed the verified fix as `9dba3e5` on `fix/sequential-gemma-generation`.

## Decisions

- Treat native cancellation completion as the boundary before a subsequent
  prompt is allowed.
- On automatic stop-token detection, request native cancellation and drain the
  response lifecycle instead of breaking the stream immediately.
- Align the install metadata with the `.litertlm` URL. Existing installations
  made with `ModelFileType.task` must be reinstalled once to update metadata.
