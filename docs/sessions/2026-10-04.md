2. **Why not contribute to `cactus-flutter`:** archived 2026-07-24; `cactus/bindings/flutter` is one `cactus.dart` with no Needle.

## Facts that bit us (verify before relying on older docs)

- **Android has no `.so`:** `needle build --platform android-arm64` gives `libneedle.a` + a `needle`
  executable + `needle.h`. The owner builds a shared library (CMake + NDK) and sets
  `-Wl,-z,max-page-size=16384`. The 0x4000 alignment measured in M0 was on the executable, not on
  anything shipped.
- **Six C functions**, not five: `needle_last_error` exists. The engine is "one process-global,
  non-thread-safe model": one worker isolate, serialised calls, no unload, one toolset per session.
- **Embedding dimension 3072**; weights 35,335,380 bytes (not bundled in the package).
- **`confidence` is not a reliable gate:** the macOS reference gave 0.1466 for a correct call; locally
  tuned weights report `null`. Gate with confirmation instead.
- **Python reference peak RAM 127.9 MB** (macOS), above the plan's 100 MB target; re-baseline on a phone.
- **Cactus's AI rule** (verbatim): *"Do not blindly PR AI slop, this codebase is very complex, they
  miss details."* A warning in the main `cactus` repo, not a ban; `needle` has no CONTRIBUTING file.
  The stricter working rules come from the owner's goal. An earlier summary of mine overstated it as
  a ban and was corrected.
- **Telemetry is on by default** in the engine; opt out with `NEEDLE_TELEMETRY=0` / `DO_NOT_TRACK=1`.
  Mobile opt-out is unverified (issue Q5; task H11).
- H8's brief once said 36 golden files; the correct count is **18** (3 sets × 6).
- The `server_base` repo has an earlier hand-written FFI prototype (static `libneedle.a`, pinned,
  sha256-checked fetch script) that answers part of M2; reuse the understanding, don't copy-paste.
