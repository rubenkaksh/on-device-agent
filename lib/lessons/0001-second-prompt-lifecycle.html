Why the second prompt fails

By the end, you will be able to read the error as a lifecycle trace and name the exact boundary the fix must protect.

The one idea

A streamed response has two lifecycles: the Flutter/Dart stream that delivers tokens, and the native prediction that produces them. They usually finish together. They are not automatically the same event.

Prompt 1
addQueryChunk(first) stages input.
Native
generateResponseAsync() starts Predict.
Dart
App sees <end_of_turn> and exits its loop.
Race
Local UI looks idle, but native prediction is still unwinding.
Prompt 2
addQueryChunk(second) arrives too early.
Native
Rejects it: AddQueryChunk should not be called before PredictDone.
Translation: “PredictDone” is the native engine saying, “I have not finished the previous turn yet.” It is a timing/state error, not a language-model-quality error.

The safe fix

  1. When the stop token is detected, call native stopGeneration().
  2. Do not break away from the native stream immediately. Drain it until the native side signals completion.
  3. Expose a completion future and await it from the Stop action.
  4. Only then permit another prompt.

That is why the corrected service uses a generation future. The future is the bridge between “the user interface is done” and “the native engine is done.”

A second, independent clue

The app downloaded a .litertlm file but recorded ModelFileType.task. The log therefore said fileType=task. Artifact type, metadata, prompt formatting, and engine selection must agree. Reinstalling is necessary after correcting stale metadata.

Quick practice

Scenario: The Stop button closes the subscription, then calls native cancellation. The user can immediately press Send. Which statement is safest?
  1. Closing the subscription proves native inference is complete.
  2. Calling cancellation is enough; no completion wait is needed.
  3. The app must wait for the native generation lifecycle to unwind before staging the next query.

Answer: C. A Dart subscription is an observation channel; the native session owns the prediction state.

One-minute property brief

maxTokens is the whole context budget, while maxOutputTokens caps only the new reply. temperature: 0.2 makes sampling conservative; topK: 40 limits each choice to the 40 most likely candidates; randomSeed: 1 makes the random component more repeatable. None of these properties fixes a lifecycle race.
