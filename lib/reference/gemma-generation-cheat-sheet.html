Gemma generation, without the mystery

A field guide for the second-prompt PredictDone failure and the properties that shape a response.

1. The lifecycle in one picture

addQueryChunk(prompt)
        ↓
generateResponseAsync()  ── native Predict is running ──→ tokens
        ↓
native done / cancellation completes
        ↓
addQueryChunk(next prompt)
Invariant: the next addQueryChunk must happen only after the previous native prediction has reached its terminal state.

2. What the error means

PredictDone() AddQueryChunk should not be called before PredictDone is a native state-machine error, not a bad prompt. The Dart stream and the native prediction are related but not identical. Closing or cancelling the Dart-side listener can detach Flutter before the native engine has finished unwinding.

In the D1 code, detecting <end_of_turn> used break. That ended the app's local loop immediately. The second tap then staged a new query while the first native Predict was still active.

The safe sequence is:

  1. request native cancellation when a stop token or Stop button is hit;
  2. keep draining the native stream until it ends;
  3. wait for the generation future to complete;
  4. only then accept the next prompt.

3. The model-file trap

Engine selection follows the registered model metadata. A URL ending in .litertlm must be installed as ModelFileType.litertlm. If the metadata says task, the app can route the same bytes through MediaPipe and format prompts differently.

Your log showed fileType=task while the app downloaded a .litertlm artifact. After changing the code, reinstall once: the old active model metadata does not rewrite itself automatically.

4. Generation properties

PropertyMeaningPractical effect
maxTokensTotal context window: system prompt + history + current input + generated output.Larger values use more memory. Too small can truncate or fail. It is not simply “reply length.”
maxOutputTokensMaximum number of tokens generated for one response.Caps runaway replies while leaving the context window intact. The current app does not set it.
temperatureScales the next-token probability distribution before sampling.Low values, such as 0.2, are steadier and more repeatable. Higher values are more varied and more error-prone.
topKRestricts sampling to the K most likely next tokens.40 removes unlikely choices but still permits variation among the likely ones.
randomSeedSeeds the sampler's random choices.Can improve repeatability, but does not promise byte-identical output across runtimes or changed history.
stop tokensSpecial markers that signal an end of turn.Prefer engine-level stopping. A Dart filter is a safety net and must still shut down native generation safely.
fileTypeDescribes the model artifact and selects prompt/engine behavior.Keep the metadata, URL, and registered engine consistent.

5. Diagnostic habit

When a second-turn failure appears, log the boundaries—not every token:

TURN 1: query staged
TURN 1: native generation started
TURN 1: stop requested
TURN 1: native stream done
TURN 1: generation future done
TURN 2: query staged

If “TURN 2: query staged” appears before “TURN 1: native stream done,” you have a lifecycle race. If the file type is wrong before generation starts, fix installation metadata first.
